# Design and acceptance

Original title, story, CSS artwork, and eight authored numeric puzzles. One fixed overhead workshop camera with incoming/outgoing conveyors, one courier, carried value, numbered memory, editable visual route, active program counter, and labeled jump destinations. No free movement: instructions move the courier. Commands unlock progressively. Route editing uses click-to-add, per-row opcode/operand editing, arrows, drag reorder, removal, labels and jump selectors. Space runs/pauses, S steps, R resets outside form fields. All controls also have buttons.

Public test seams: deterministic create/step/execute/certify VM functions, authored puzzle reference solutions, and browser-visible editor/transport/progression/save interactions. These are authorized by the user's explicit request for VM, solution and browser tests. No optional interview: the user's instruction to choose a complete scope supersedes Grill's interview loop.

Each batch begins with fresh memory. A wrong output fails immediately. Falling off the program or exhausting INBOX ends execution and checks output length. Empty hands/memory fail with actionable errors. Conditional jumps need hands and never consume them. INBOX replaces hands; OUTBOX consumes hands. COPYTO preserves hands. Bumps update memory and hands, including when hands started empty. Jumps target stable instruction labels and count as one execution step. Labels cost no extra instruction or step. Safety budget is 10,000 steps; numeric range is -999..999. Certification checks every deterministic batch, including empty and adversarial cases, and reports the first failing batch; this is finite validation, not proof. Size and worst-batch steps are optional medals, never correctness gates.

Local persistence validates stored routes and completion IDs, with graceful handling of unavailable storage. Program edits reset runtime. Completed assignments unlock the next; completed assignments remain editable.

Omissions/differences: numeric boxes only, direct memory addressing only, no letter arithmetic, indirect addressing, comments, undo, sound, original levels, original art, or original story. Goal metrics use a fixed published case bank rather than randomized averages. Animation is a schematic courier transition, not skeletal character animation. No commercial game assets or code.

Research: Tomorrow Corporation's official Human Resource Machine page (https://tomorrowcorporation.com/humanresourcemachine), accessed 2026-10-16, establishes single accumulator, inbox/outbox, floor memory, drag commands, gradual unlocks, size/speed challenges and fixed overhead gameplay imagery. Fine instruction rules are explicitly specified above and tested as this game's contract; no claim that the official page documents every edge case.
